# Приёмка (AUDIT) и синхронизация `docs/` с шаблонами

**Дата:** 2026-04-27  
**Контекст:** отчёт по приёмке смотрел **собранный** сайт на GitHub Pages; часть замечаний относилась к устаревшему или неполному содержимому папки `docs/`, а не к отсутствию логики в Django-шаблонах.

---

## 1. Как читать отчёт приёмки относительно репозитория

**Кратко:** проверяющий смотрел задеплоенный `github.io` (старый или частично обновлённый `docs/`). В **исходных шаблонах** часть пунктов уже была закрыта; расхождение в основном между `templates/` и тем, что попало в статический `docs/`, плюс несколько реальных правок в шаблонах и медиа для Pages.

### Уже было в шаблонах, но не совпадало с деплоем

| Тема приёмки | В `templates/` | Проблема на сайте |
|--------------|----------------|-------------------|
| Четыре главные CTA (модалки `home_private_choice`, `home_b2b_choice`, `home_gazon_excursion`, `pitomnik_open_day_signup`) | Все `<template>` есть в `partials/modals.html` | В `docs/index.html` модальный блок был **обрезан**: скрипт `export_home_to_docs.py` раньше обновлял только `<main>`, футер и модалки не пересобирались из актуального `base.html`. |
| Поле «Тема консультации» в `contact_consult` | Уже есть (`textarea` в `modals.html`) | В `docs/index.html` оставалась старая версия формы (имя + телефон). |
| Полная форма ДОД (`pitomnik_open_day_signup`) | В `modals.html` уже полная (даты, тип клиента, количество гостей, согласие) | `docs/gazon/index.html` был актуальнее; **`docs/pitomnik/index.html`** отставал (старая разметка с чекбоксами без типа клиента и гостей). |
| Картинки кейсов озеленения B2C | Файлы есть в `static/media/images/cases/` | В **`docs/static/.../cases/`** копий не было → 404 на Pages при том, что ассеты в репо уже были. |

**Итог одной фразой:** на GitHub Pages было видно «дыры», потому что **`docs/` отставал от шаблонов**; переписывать модалки и поля формы заново не требовалось — нужно было **выровнять деплой** с исходниками и поправить узкие места (ссылки B2B, медиа).

### Что в отчёте приёмки оставалось в силе как отдельная работа

- **Жёсткие ссылки** в карточках B2B (`/gazon/`, `/pitomnik/` без префикса репозитория) — реальная ошибка в **`templates/pages/b2b.html`** для GitHub Pages.
- **CLS / Tailwind в браузере**, тяжёлое hero-видео, security-заголовки на `github.io`, интеграции MAX/soft3k, адрес СЦ — по смыслу отчёта без изменений (архитектура, хостинг, контент, отдельные спринты).

## 2. Что сделано в репозитории (синхронизация и правки)

### 2.1. `templates/pages/b2b.html`

Три ссылки «Подробнее» переведены на `{% url 'gazon' %}` и `{% url 'pitomnik' %}` — после экспорта в статике получаются пути с префиксом `/sib_khvoinik_test/...`, ссылки на Pages не дают 404.

### 2.2. `scripts/export_home_to_docs.py`

Скрипт **полностью перезаписывает** `docs/index.html` из рендера `pages/home.html` (как `export_consent_to_docs.py`): главная, шапка, подвал, **все модалки**. Подставляется префикс `SITE_PREFIX` (по умолчанию `/sib_khvoinik_test`) для `/static/` и внутренних `href`/`src`, в `<meta name="base-path">` записывается тот же префикс для клиентского JS.

### 2.3. Новые скрипты экспорта

- **`scripts/export_pitomnik_to_docs.py`** — полный `docs/pitomnik/index.html` из `pages/pitomnik.html` + `PITOMNIK_PAGE`.
- **`scripts/export_b2b_to_docs.py`** — полный `docs/b2b/index.html` из `pages/b2b.html` + `B2B_PAGE`.

Та же схема префиксов и `base-path`, что и у главной/согласия.

### 2.4. Медиа для GitHub Pages

Три файла `ozelenenie-b2c-case-01.png` … `03.png` скопированы в **`docs/static/media/images/cases/`**. В **`.gitignore`** добавлены исключения `!docs/static/media/images/cases/ozelenenie-b2c-case-0X.png`, иначе глобальное правило `*.png` не позволило бы закоммитить копии для деплоя.

### 2.5. Перегенерированные страницы

После правок скриптов выполнен экспорт (через локальный `.venv` с `requirements.txt`): обновлены **`docs/index.html`**, **`docs/pitomnik/index.html`**, **`docs/b2b/index.html`**.

### 2.6. Документация для разработчиков

В **`CLAUDE.md`** в блок команд добавлены `export_pitomnik_to_docs.py` и `export_b2b_to_docs.py`, уточнено, что `export_home_to_docs.py` пересобирает **полный** `index.html` включая модалки.

## 3. Как поддерживать актуальность `docs/`

После изменений в `base.html`, `partials/modals.html`, `home.html`, `pitomnik.html`, `b2b.html` или связанных данных:

```bash
pip install -r requirements.txt   # при необходимости
python scripts/export_home_to_docs.py
python scripts/export_pitomnik_to_docs.py
python scripts/export_b2b_to_docs.py
```

Префикс при другом пути на Pages: `SITE_PREFIX=/ваш-префикс python scripts/export_home_to_docs.py` (и аналогично для остальных скриптов).

## 4. Связь с исходным AUDIT_REPORT

Блокеры приёмки про **битые модалки на главной**, **отсутствие темы в консультации в HTML**, **битые ссылки B2B**, **битые фото кейсов** и **разные формы ДОД на питомнике** с точки зрения **задеплоенного** сайта были обоснованы. После описанных правок репозиторий приводит статику в соответствие с уже существующей разметкой в `templates/` и закрывает явные ошибки B2B и медиа для GitHub Pages. Остальные пункты аудита (CLS, видео, MAX, координаты СЦ и т.д.) этим коммитом не затрагиваются.
