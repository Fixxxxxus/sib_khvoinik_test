  Схема маппинга: Старый → Новый

  Каталог

  СТАРЫЙ                              НОВЫЙ
  ─────────────────────────────────── ──────────────────────────────────
  /product/                        →  /katalog/
  /product/{категория}/            →  /katalog/{категория}/
  /product/{категория}/{подкат}/   →  /katalog/{категория}/{подкат}/   (*)
  /product/{.../}{товар}/          →  /katalog/{slug-товара}/

  (*) Решение по глубине:
  - Сейчас у тебя 2 уровня: /katalog/ и /katalog/<slug>/
  - У старого сайта 3 уровня: категория → подкатегория → товар
  - Best practice: Плоский каталог /katalog/<category>/ + карточка /katalog/<plant-slug>/ — как уже
  сделано. Подкатегории реализуются фильтрами внутри категории, а не вложенными URL. Это проще,
  устойчивее, и SEO-дружелюбнее для статического сайта.

  смысла делать 3 отдельных раздела для 20-30 записей суммарно.

  301-редиректы (критически важно для SEO)

  Для статического сайта на GitHub Pages — файл docs/_redirects не работает. Best practice:

  1. HTML meta-refresh файлы — для каждого старого URL создаём docs/product/index.html с <meta
  http-equiv="refresh" content="0;url=/katalog/"> + canonical
  2. Или — если домен gazony.ru переезжает на Timeweb, настраиваем 301 на уровне nginx/htaccess на
  хостинге, что правильнее

  ---
  Главный принцип: не тянем сложность Bitrix. Плоская структура, контент в data.py, статический
  экспорт. Редиректы — единственная "сложная" часть, и ту можно сгенерить скриптом из sitemap.
